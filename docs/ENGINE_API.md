# Calendar engine API (W4)

```js
import { createCalendar } from './engine/calendar.mjs';
const cal = await createCalendar();          // browser: fetches engine/calgen/rulebook/* and data/calendar/*; node: reads files
const day = cal.resolveDay('2027-03-28');    // 'YYYY-MM-DD', 'M/D/YYYY', {y,m,d}, or a Date (read as its LOCAL civil date). Years 1583-9999.
```
A typed date is a civil date: no clock, no time zone, so it never shifts (tested under America/New_York, UTC, Pacific/Auckland).
Invalid input returns `{schema, error}`; nothing is guessed.

## Record (`schema: liturgical-day/1.0`)
`date, weekday, year, civil, easter, easterOffset, mode{number,armenian,since}, table, status('placed'|'unresolved'|'no_readings_appointed'), provisional`
- `commemorations[]`: `armenian, bookHeadingArmenian, english, englishStatus('sourced'|'composed'|null), englishProvenance, role, kind, recordOrdinal, rule, ruleStatus, series[]`. `sourced` = a published English name (Vemkar / ACHR); `composed` = built from components, not a published name.
- `fasting`: `status, label, rule, ruleStatus, basis, provisional, openQuestions[]` (every day has a definite status; `openQuestions` is empty for fasting since 2026-10-25: Lenten Saturdays and Sundays are not fasts by the owner's ruling, the Elijah / St Gregory fasts are confirmed by Hador 1 and the printed directories; `feastKept` is true for the Annunciation inside Holy Week, a fast with the feast kept).
- `readings[]` (Divine Liturgy / Jashoo set first by `service.class`): `verbatimArmenian` (Hador 1), `passage` {book,ch,v}, `citationKey`, `citationEn` (composed from the parse; numbered books matched exactly), `citationEnSource`, `citationIndexMatch('exact'|'overlapping...'|'none')`, `book`, `bookHy`, `kind`, `endPrinted`, `service{class,label,basis,share,confident,alternatives,level}`, `arak29{shard,key}` (pointer to the Armenian Bible text in `data/scripture/arak29/t/<shard>.json`), `versification{status('match'|'differs'|'needs_review'|...),note,compound}` (Armenian vs English verse numbering; English requested for the corrected range), `jashots{chains[{chain_id,pdf_pages,printed_page}],introEn,introHy}` (printed-page transcription, second layer), `flags`, `needsPageCheck`, `reason`.
  Service class is printed in Hador 1 when present; otherwise learned from the 2001-2040 tables per (Hador 1 record, passage) and flagged `confident:false` when ambiguous. Record-level supplements (readings a Hador 1 record prints only partly) carry `basis`/`evidence` (source-attested or `learned_from_reconciled`). Impossible printed references are repaired only through an explicit reviewed table. `secondaryReadings[]`: readings of a later commemoration on collision days (the first commemoration with readings governs).
- `chants[]` and `chantLayout`: psalm / meseti / alleluia lines from Hador 1 with `kind, service, verbatim, incipit, psalm, precedes_reading(_key), service_order, group, order_basis, order_rule, opening{rule_id,applies,armenian_prefix,english_prefix,confidence,evidence}` (Alleluia opening line, rule from Fr Arshen's Lectionary), `armenian_full`, `english_full`, `english_source` (ESV via live lookup / KJV / AI translation labelled), `refs` (Armenian LXX numbering and English numbering), `review_status`. `chantLayout.groups[].items[]` is the service-ordered list (chant, reading, chant, ...) for rendering. 'X ՚ի ձայնէն' rubrics are resolved from the Zhamagirk generic table by category + commemoration + mode (`data/calendar/generic_chants.json`).
- `fasting` additionally carries `name`, `extent`, `feastKept`; every day has `status` in `fast|not_fast|feast` (closing rule `R-FAST-NONE`).
- `hymns[]`: `source('hador1 #n'|'hador2 id'), sources, type, incipit, mode, status('linked_exact'|'linked_section'|'ambiguous'|'unlinked'|'direction'), resolved{hymnId,sectionId,sectionTitle,sectionPage,sectionKind,page,pagesAll,stanzaN,incipit,mode,n_stanzas,basis,confidence,generic}, candidates[<=3], basis, confidence, needsReview, method, note`. A resolved hymn has exactly ONE `page`; an `ambiguous`/`unlinked` hymn has `resolved:null` and shows no page (candidates are not a decision). `direction` = a rubric instruction («զՈղորմեայն ասա»), not an opening. The old `links[]` array is kept for older renderers.
- `canon` (`schema: day-canon/1.0`, contract `output/site_build/H1_CANON_CONTRACT.md` in the project repo): `canons[]` (primary/secondary canons of the day), `parts[]` in book order (`orhnutyun, harts (with its Gordzk), metsatsutse, voghormya, der_hergnits, mankunk, jashoo, hampartsi`) each with `status('present'|'from_rubric'|'not_in_data'|'not_applicable'|'missing')`, `source` (`canon`, `generic_eight_modes`, `generic_kind`, `generic_rule`, `generic_same_canon`, `rubric`, ...), `complete`, `service{service('night'|'morning'|'divine_liturgy'|'evening'),label,slot,evidence,confidence,dayHasService}`, `needsReview`, `candidates`, and `hymns[]` (`hymnId, incipit, mode, page, pagesAll, stanzaIds, heading, subpart, partBasis, namedByRubric, cues, ode/odeSet/toneSet, basis, confidence`). When a canon is printed by tone, only the day's own tone block is used (a stated gap otherwise). `sharagnots[]` groups the resolved hymns by section for older renderers.
- `canons[]`: canon-level links from Hador 1 records to Sharagnots sections (`mapped:false` when the canon title has no section match).
- `unresolved[]`: every field the engine could not settle, with the reason. `provenance`: the claims (rule id, status, records, pages) behind the day.

## Data (data/calendar, rebuilt by tools/)
`readings_index.json` (passage -> Jashots chain ids, pages, intro lines, service observations), `record_service.json` (record|passage -> service), `record_supplements.json`, `chapter_verses.json`, `versification.json`, `psalm_crosswalk.json` (LXX/MT psalm numbering), `hymn_index.json` (Sharagnots hymns with evidence-ranked modes), `hymn_openings.json`, `hymn_aliases.json`, `canon_parts.json`, `canon_marks.json`, `ode_marks.json`, `cue_lines.json`, `record_canons.json`, `chants_layer.json`, `chants_english.json`, `generic_chants.json`.
Rebuild: `python3 tools/build_calendar_data.py && node tools/build_service_table.mjs`. Check: `node tests/test_calendar.mjs`, `node tools/validate_vs_final.mjs`.
